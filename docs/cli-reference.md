```
fleetctl [OPTIONS] COMMAND [ARGS]...

  -V, --version      Show the version and exit.
  -v, --verbose      Increase log verbosity; repeat for debug.
  --config-dir PATH  Directory holding fleet.yml and inventory/. Defaults to ./config.
  --home PATH        Runtime state directory. Defaults to ~/.fleetctl.
  -h, --help         Show this message and exit.
```

`-v` maps to WARNING at 0, INFO at 1, DEBUG at 2+. `--home` is where operation staging, audit logs, forensics (preserved failed workspaces), and local artifacts (if not on SMB) live.

<h2 style="border-left: 6px solid #005288; padding: 4px 0 10px 16px; margin: 40px 0 16px; border-bottom: 1px solid rgba(0, 82, 136, 0.25); background-image: url(data:image/svg+xml;utf8,%3Csvg%20xmlns%3D%27http%3A%2F%2Fwww.w3.org%2F2000%2Fsvg%27%20width%3D%27100%25%27%20height%3D%27100%25%27%3E%3Cdefs%3E%3Cpattern%20id%3D%27h%27%20width%3D%2720%27%20height%3D%2735%27%20patternUnits%3D%27userSpaceOnUse%27%3E%3Cpath%20d%3D%27M10%2023L0%2018V6L10%200l10%206v12L10%2023zm0%200v12%27%20fill%3D%27none%27%20stroke%3D%27%23005288%27%20stroke-opacity%3D%270.22%27%2F%3E%3C%2Fpattern%3E%3ClinearGradient%20id%3D%27lg%27%20x1%3D%270%25%27%20x2%3D%27100%25%27%3E%3Cstop%20offset%3D%270%25%27%20stop-color%3D%27white%27%20stop-opacity%3D%271%27%2F%3E%3Cstop%20offset%3D%2785%25%27%20stop-color%3D%27white%27%20stop-opacity%3D%270%27%2F%3E%3C%2FlinearGradient%3E%3Cmask%20id%3D%27f%27%3E%3Crect%20width%3D%27100%25%27%20height%3D%27100%25%27%20fill%3D%27url%28%23lg%29%27%2F%3E%3C%2Fmask%3E%3C%2Fdefs%3E%3Crect%20width%3D%27100%25%27%20height%3D%27100%25%27%20fill%3D%27url%28%23h%29%27%20mask%3D%27url%28%23f%29%27%2F%3E%3C%2Fsvg%3E); background-size: 100% 100%; background-repeat: no-repeat; border-radius: 3px;">`scan`</h2>

```
fleetctl scan [OPTIONS] SUBNET

  --dry-run   Report what was found without writing the inventory.
```

Sweeps `SUBNET`, identifies hosts against every installed device pack, and merges what it finds into `config/inventory/devices.yml`. Never touches `tags` or `vars` on a device already known — hand-edit those. A device that answers but refuses the ADB key is recorded anyway, flagged `unauthorized` so it's visible rather than silently dropped.

<div align="left" style="position: relative; z-index: 1; margin-left: 10px; margin-bottom: -10px;"><img src="assets/lang-bash.svg" height="18"/></div>

```bash
fleetctl scan 192.168.1.0/24
fleetctl scan 192.168.1.0/24 --dry-run
```

Also available as the `fleet.scan` step (`fleetctl run fleet.scan --set subnet=192.168.1.0/24`) and the shipped `fleet-scan` workflow — the step form is what a workflow, MCP, or a future integration would use; the top-level command is the same operation with richer terminal output (per-host detail, "N hosts refused this key" summary).

<h2 style="border-left: 6px solid #005288; padding: 4px 0 10px 16px; margin: 40px 0 16px; border-bottom: 1px solid rgba(0, 82, 136, 0.25); background-image: url(data:image/svg+xml;utf8,%3Csvg%20xmlns%3D%27http%3A%2F%2Fwww.w3.org%2F2000%2Fsvg%27%20width%3D%27100%25%27%20height%3D%27100%25%27%3E%3Cdefs%3E%3Cpattern%20id%3D%27h%27%20width%3D%2720%27%20height%3D%2735%27%20patternUnits%3D%27userSpaceOnUse%27%3E%3Cpath%20d%3D%27M10%2023L0%2018V6L10%200l10%206v12L10%2023zm0%200v12%27%20fill%3D%27none%27%20stroke%3D%27%23005288%27%20stroke-opacity%3D%270.22%27%2F%3E%3C%2Fpattern%3E%3ClinearGradient%20id%3D%27lg%27%20x1%3D%270%25%27%20x2%3D%27100%25%27%3E%3Cstop%20offset%3D%270%25%27%20stop-color%3D%27white%27%20stop-opacity%3D%271%27%2F%3E%3Cstop%20offset%3D%2785%25%27%20stop-color%3D%27white%27%20stop-opacity%3D%270%27%2F%3E%3C%2FlinearGradient%3E%3Cmask%20id%3D%27f%27%3E%3Crect%20width%3D%27100%25%27%20height%3D%27100%25%27%20fill%3D%27url%28%23lg%29%27%2F%3E%3C%2Fmask%3E%3C%2Fdefs%3E%3Crect%20width%3D%27100%25%27%20height%3D%27100%25%27%20fill%3D%27url%28%23h%29%27%20mask%3D%27url%28%23f%29%27%2F%3E%3C%2Fsvg%3E); background-size: 100% 100%; background-repeat: no-repeat; border-radius: 3px;">`run`</h2>

```
fleetctl run [OPTIONS] STEP_ID

  --device TEXT    Target device id. Required for device-scoped steps.
  --set KEY=VALUE  Config override for this run; repeatable.
  --approve        Approve a step the policy flagged as needing it.
```

Runs one registered step directly, outside a workflow. `fleetctl steps` lists what's available.

<div align="left" style="position: relative; z-index: 1; margin-left: 10px; margin-bottom: -10px;"><img src="assets/lang-bash.svg" height="18"/></div>

```bash
fleetctl run firetv.check --device living-room-stick
fleetctl run kodi.deploy --device living-room-stick --approve
fleetctl run fleet.scan --set subnet=192.168.1.0/24 --set dry_run=true
```

**`--set` keys nest on dots** and their values parse as YAML scalars — `--set kodi.display.resolution_index=18` produces `{"kodi": {"display": {"resolution_index": 18}}}` (an int, not the string `"18"`), which merges with a device's own `vars.kodi` instead of replacing the whole branch. This is how a resolution or overscan value can be tried without editing the inventory first — see [`configuration.md`](configuration.md#device-vars) for what a device-scoped step normally reads from `vars`.

**`--approve`** satisfies a `confirm` verdict from the policy (see [`safety.md`](safety.md)). Without it, a step the policy flagged is refused with the reason and told to re-run with `--approve` — nothing runs partially.

<div style="margin-top: 52px; margin-left: 10px; color: #7986cb; font-size: 10.5px; font-weight: 700; letter-spacing: 2px; line-height: 1;">&#9642; REFERENCE &middot; Command</div>
<h3 style="margin-top: 4px; margin-left: 10px;">`workflow list`</h3>

<div align="left" style="position: relative; z-index: 1; margin-left: 10px; margin-bottom: -10px;"><img src="assets/lang-bash.svg" height="18"/></div>

```bash
fleetctl workflow list
```

Every shipped workflow plus any user-defined ones in `config/workflows/`. Shipped:

| Name | Steps | What it does |
|---|---|---|
| `fleet-scan` | 1 | Sweep the configured subnet and merge results. Default subnet is set in the workflow; override with `--set subnet=...` on `workflow run`. |
| `fleet-maintenance` | 2 | Debloat, apply performance settings, trim caches across every tagged device. Touches no Kodi profile. |
| `kodi-check` | 2 | Read-only health sweep — device facts, free space, whether a newer stable Kodi exists. Needs no approval under any policy. |
| `kodi-capture-gold` | 2 | Capture the `gold`-tagged device's live profile and rebuild from it. Nothing deployed. |
| `kodi-deploy-all` | 2 | Push the current published build to every `kodi`-tagged device, without rebuilding it. |
| `kodi-refresh` | 6 | The full roll-out: fetch latest stable Kodi, rebuild from the latest capture, maintain then deploy every device, then reapply per-device display/settings. |

A user-defined workflow with the same name as a shipped one shadows it — shipping a workflow never takes an option away.

<div style="margin-top: 52px; margin-left: 10px; color: #7986cb; font-size: 10.5px; font-weight: 700; letter-spacing: 2px; line-height: 1;">&#9642; REFERENCE &middot; Command</div>
<h3 style="margin-top: 4px; margin-left: 10px;">`workflow plan`</h3>

```
fleetctl workflow plan NAME
```

Shows every task the workflow would run — which step, which device, its effect class, whether it's blocked or needs approval — without doing any of it. Prints a digest.

<div align="left" style="position: relative; z-index: 1; margin-left: 10px; margin-bottom: -10px;"><img src="assets/lang-bash.svg" height="18"/></div>

```bash
fleetctl workflow plan kodi-refresh
```

<div style="margin-top: 52px; margin-left: 10px; color: #7986cb; font-size: 10.5px; font-weight: 700; letter-spacing: 2px; line-height: 1;">&#9642; REFERENCE &middot; Command</div>
<h3 style="margin-top: 4px; margin-left: 10px;">`workflow run`</h3>

```
fleetctl workflow run [OPTIONS] NAME

  --dry-run       Show the plan and stop.
  --confirm TEXT  Refuse to run unless the plan still matches this digest.
  --approve       Approve tasks the policy flagged as needing it.
```

`--confirm` must be the digest `workflow plan` just printed. If the fleet changed since — a device added, a tag edited — the digest won't match and the run is refused. This is deliberate: a workflow never runs against a plan nobody looked at.

<div align="left" style="position: relative; z-index: 1; margin-left: 10px; margin-bottom: -10px;"><img src="assets/lang-bash.svg" height="18"/></div>

```bash
fleetctl workflow plan kodi-check                                    # note the digest
fleetctl workflow run kodi-check --confirm <digest>
fleetctl workflow run kodi-refresh --confirm <digest> --approve      # destructive steps inside
```

<div align="left" style="position: relative; z-index: 1; margin-left: 10px; margin-bottom: -10px;"><img src="assets/lang-bash.svg" height="18"/></div>

fleetctl devices list

Every device in the inventory, with status (`ok`, `unauthorized`, etc.) and tags. Read-only — edit `config/inventory/devices.yml` directly, or run `scan` to refresh what a probe can observe.

<h2 style="border-left: 6px solid #005288; padding: 4px 0 10px 16px; margin: 40px 0 16px; border-bottom: 1px solid rgba(0, 82, 136, 0.25); background-image: url(data:image/svg+xml;utf8,%3Csvg%20xmlns%3D%27http%3A%2F%2Fwww.w3.org%2F2000%2Fsvg%27%20width%3D%27100%25%27%20height%3D%27100%25%27%3E%3Cdefs%3E%3Cpattern%20id%3D%27h%27%20width%3D%2720%27%20height%3D%2735%27%20patternUnits%3D%27userSpaceOnUse%27%3E%3Cpath%20d%3D%27M10%2023L0%2018V6L10%200l10%206v12L10%2023zm0%200v12%27%20fill%3D%27none%27%20stroke%3D%27%23005288%27%20stroke-opacity%3D%270.22%27%2F%3E%3C%2Fpattern%3E%3ClinearGradient%20id%3D%27lg%27%20x1%3D%270%25%27%20x2%3D%27100%25%27%3E%3Cstop%20offset%3D%270%25%27%20stop-color%3D%27white%27%20stop-opacity%3D%271%27%2F%3E%3Cstop%20offset%3D%2785%25%27%20stop-color%3D%27white%27%20stop-opacity%3D%270%27%2F%3E%3C%2FlinearGradient%3E%3Cmask%20id%3D%27f%27%3E%3Crect%20width%3D%27100%25%27%20height%3D%27100%25%27%20fill%3D%27url%28%23lg%29%27%2F%3E%3C%2Fmask%3E%3C%2Fdefs%3E%3Crect%20width%3D%27100%25%27%20height%3D%27100%25%27%20fill%3D%27url%28%23h%29%27%20mask%3D%27url%28%23f%29%27%2F%3E%3C%2Fsvg%3E); background-size: 100% 100%; background-repeat: no-repeat; border-radius: 3px;">`packs`</h2>

<div align="left" style="position: relative; z-index: 1; margin-left: 10px; margin-bottom: -10px;"><img src="assets/lang-bash.svg" height="18"/></div>

```bash
fleetctl packs
```

Installed device packs (`firetv`, `shield`) and app packs (`kodi`), with each device pack's platform and declared capabilities (`exec`, `files`, `power`, `reach`, `state`, `apps`, `facts`, `cleanup`, `settings`).

<h2 style="border-left: 6px solid #005288; padding: 4px 0 10px 16px; margin: 40px 0 16px; border-bottom: 1px solid rgba(0, 82, 136, 0.25); background-image: url(data:image/svg+xml;utf8,%3Csvg%20xmlns%3D%27http%3A%2F%2Fwww.w3.org%2F2000%2Fsvg%27%20width%3D%27100%25%27%20height%3D%27100%25%27%3E%3Cdefs%3E%3Cpattern%20id%3D%27h%27%20width%3D%2720%27%20height%3D%2735%27%20patternUnits%3D%27userSpaceOnUse%27%3E%3Cpath%20d%3D%27M10%2023L0%2018V6L10%200l10%206v12L10%2023zm0%200v12%27%20fill%3D%27none%27%20stroke%3D%27%23005288%27%20stroke-opacity%3D%270.22%27%2F%3E%3C%2Fpattern%3E%3ClinearGradient%20id%3D%27lg%27%20x1%3D%270%25%27%20x2%3D%27100%25%27%3E%3Cstop%20offset%3D%270%25%27%20stop-color%3D%27white%27%20stop-opacity%3D%271%27%2F%3E%3Cstop%20offset%3D%2785%25%27%20stop-color%3D%27white%27%20stop-opacity%3D%270%27%2F%3E%3C%2FlinearGradient%3E%3Cmask%20id%3D%27f%27%3E%3Crect%20width%3D%27100%25%27%20height%3D%27100%25%27%20fill%3D%27url%28%23lg%29%27%2F%3E%3C%2Fmask%3E%3C%2Fdefs%3E%3Crect%20width%3D%27100%25%27%20height%3D%27100%25%27%20fill%3D%27url%28%23h%29%27%20mask%3D%27url%28%23f%29%27%2F%3E%3C%2Fsvg%3E); background-size: 100% 100%; background-repeat: no-repeat; border-radius: 3px;">`artifacts list`</h2>

```
fleetctl artifacts list KIND
```

Lists stored artifacts of one kind — `captures`, `builds`, or `gold` — newest first, from whichever backend `fleet.yml` configures (SMB or local).

```bash
fleetctl artifacts list builds
```

<h2 style="border-left: 6px solid #005288; padding: 4px 0 10px 16px; margin: 40px 0 16px; border-bottom: 1px solid rgba(0, 82, 136, 0.25); background-image: url(data:image/svg+xml;utf8,%3Csvg%20xmlns%3D%27http%3A%2F%2Fwww.w3.org%2F2000%2Fsvg%27%20width%3D%27100%25%27%20height%3D%27100%25%27%3E%3Cdefs%3E%3Cpattern%20id%3D%27h%27%20width%3D%2720%27%20height%3D%2735%27%20patternUnits%3D%27userSpaceOnUse%27%3E%3Cpath%20d%3D%27M10%2023L0%2018V6L10%200l10%206v12L10%2023zm0%200v12%27%20fill%3D%27none%27%20stroke%3D%27%23005288%27%20stroke-opacity%3D%270.22%27%2F%3E%3C%2Fpattern%3E%3ClinearGradient%20id%3D%27lg%27%20x1%3D%270%25%27%20x2%3D%27100%25%27%3E%3Cstop%20offset%3D%270%25%27%20stop-color%3D%27white%27%20stop-opacity%3D%271%27%2F%3E%3Cstop%20offset%3D%2785%25%27%20stop-color%3D%27white%27%20stop-opacity%3D%270%27%2F%3E%3C%2FlinearGradient%3E%3Cmask%20id%3D%27f%27%3E%3Crect%20width%3D%27100%25%27%20height%3D%27100%25%27%20fill%3D%27url%28%23lg%29%27%2F%3E%3C%2Fmask%3E%3C%2Fdefs%3E%3Crect%20width%3D%27100%25%27%20height%3D%27100%25%27%20fill%3D%27url%28%23h%29%27%20mask%3D%27url%28%23f%29%27%2F%3E%3C%2Fsvg%3E); background-size: 100% 100%; background-repeat: no-repeat; border-radius: 3px;">`audit`</h2>

<div style="margin-top: 52px; margin-left: 10px; color: #7986cb; font-size: 10.5px; font-weight: 700; letter-spacing: 2px; line-height: 1;">&#9642; REFERENCE &middot; Command</div>
<h3 style="margin-top: 4px; margin-left: 10px;">`audit tail`</h3>

```
fleetctl audit tail [OPTIONS]

  -n INTEGER  How many records to show.  [default: 20]
```

The most recent audit records — one per mutating or destructive effect, redacted, hash-chained. See [`observability.md`](observability.md) for what's recorded and why.

<div style="margin-top: 52px; margin-left: 10px; color: #7986cb; font-size: 10.5px; font-weight: 700; letter-spacing: 2px; line-height: 1;">&#9642; REFERENCE &middot; Command</div>
<h3 style="margin-top: 4px; margin-left: 10px;">`audit verify`</h3>

<div align="left" style="position: relative; z-index: 1; margin-left: 10px; margin-bottom: -10px;"><img src="assets/lang-bash.svg" height="18"/></div>

```bash
fleetctl audit verify
```

Verifies the audit trail's hash chain is unbroken from wherever it last resumed. A broken chain means a record was edited or deleted outside `fleetctl` itself.

```
fleetctl mcp [OPTIONS]

  --actor TEXT  Identity recorded on every audit record and matched against policy.
```

Serves the agent toolkit over MCP on stdio — 7 tools, 5 read-only resources. See [`ha-parity.md`](ha-parity.md) for the full tool list and how it maps to a Home Assistant panel's needs.
